# 1Password Desktop SDK validation procedure

This procedure requires explicit approval for the exact disposable item, the intended test actions, and use of the local desktop application. The normal build, test and CI pipeline uses the offline fixture.

1. Prepare a dedicated SSH Key item in a 1Password test vault and record its expected public fingerprint. Obtain approval for listing vault and SSH Key item metadata on the test account. Record Windows architecture, 1Password desktop version, and SDK version. Keep actual account and item identifiers out of public evidence.
2. In the local 1Password application, verify the signed-in test account and SDK desktop integration setting. The operator owns any settings change. Launch the production Release tray with a fresh test configuration. Set the opssh account scope default to exclude before connecting and leave vault rules inherited.
3. Connect from the opssh tray using the exact test account name. Inspect the official 1Password prompt and verify the requesting core process and account scope before approving. Confirm metadata discovery and an empty public index. Expand the test vault, explicitly include only the disposable item and apply. Check that its public-only reference resolves the expected canonical key and fingerprint. Test `ssh-add -L` against the opt-in process-local pipe. If the public field selector fails, record the failure and stop before requesting the private field.
4. With the public key in a temporary public file, use system `ssh-keygen -Y sign` on a generated local message and verify with `ssh-keygen -Y verify`. Approve only the exact signing request in the opssh window. This performs local signing without an SSH connection. Compare the derived identity to the index and retain only the public fingerprint, algorithm, timings and outcome.
5. Repeat with a denied or canceled prompt, a changed test item's public key, and a late provider response if reproducible. Verify the UI distinguishes provider failures from loaded keys. Exclude the test item and verify it is withdrawn from the index and its old approval cannot sign. Re-include it and verify a subsequent request needs a new approval. Observe that locking 1Password revokes its read grant, while already loaded material follows opssh's local policy. Confirm that explicit refresh retires the old index and local state.
6. Exit through the tray and restore the test shell's prior agent selection. Close the test configuration, retain only sanitized evidence and identify any unexercised conditions.

The production adapter uses the public `WithDesktopAppIntegration`, `Vaults.List`, `Items.List` and `Secrets.Resolve` interfaces. The private reference uses the documented `private key?ssh-format=openssh` selector. The public field is tested independently in step 3. Discovery uses item overviews and field references.

Sources: [SDK setup](https://www.1password.dev/sdks), [secret reference formats](https://www.1password.dev/sdks/concepts#ssh-format), [Go desktop implementation v0.4.1](https://github.com/1Password/onepassword-sdk-go/blob/f60aea196b471a9c35ddad5f9096e5fd2b5c939c/internal/shared_lib_core_windows.go).
